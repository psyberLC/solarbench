# Results

Result files as `scripts/evaluate.py` wrote them, plus the tables and media built from them.

- `<task>/<policy>_<split>_<backend>.json`: one evaluation. A later run of the same cell gets its commit appended to the name. Per-episode records, the summary with intervals, and provenance (commit, clean tree, package versions, GPU, physics backend). The shape is fixed by [`solarbench/eval/schema.py`](../solarbench/eval/schema.py) and checked by the unit tests.
- `RESULTS.md`: the summary table, regenerated by `scripts/make_results_table.py`. Do not edit by hand.
- `media/`: the demo videos (`solarbench_t2_demo.mp4`, `solarbench_t3_demo.mp4`), and under `raw/` the clips and per-step traces they were composed from.

## Rules
1. **Append-only.** A result file is never edited or overwritten. A re-run gets a new file.
2. **Only rankable results count as findings.** A result is rankable if `rankable()` returns nothing: `test` split, a recorded commit, a clean tree. Tables show every row and mark which are rankable.
3. **Privileged results are a ceiling.** The oracle reads exact simulator state. Its score says what the body can do, not what a model can do.
4. **Everything is kept.** Failed cells and results that contradict expectations are committed with the rest.

Results made before the provenance fields existed validate but are not rankable; they are kept as history.
